Research · GPU Inference Performance

vLLM Inference Runtime
on AMD ROCm MI300X

Two structured benchmarking studies on a single AMD MI300X — a dense model (Llama-3.1-8B-Instruct) and a MoE/latent-attention model (DeepSeek-V2-Lite). Every experiment follows the same loop: measure a bottleneck, attribute it to a hardware resource with roofline analysis, change a software knob, and prove the result with rocprofv3 / Omniperf evidence.

Study 1 · Dense Architecture

Llama-3.1-8B-Instruct on MI300X

Baseline → concurrency → KV-cache exhaustion → FP8 → AITER → composition → roofline, on a single MI300X.

Throughput scales 192.6 → 5,595.3 tok/s (29×) via concurrency alone; FP8 adds a further +55.0% at the knee for +0.34% perplexity; AITER is roofline-predicted and confirmed to be ~neutral (‑0.1%) on this dense architecture.

Study 2 · MoE + Latent Attention

DeepSeek-V2-Lite on MI300X

Same methodology on a MoE + MLA architecture (15.7B total / 2.4B active) — testing whether the dense-model playbook holds when the model itself is architecturally different.

AITER becomes the single largest lever measured in either study: +38.7% vs. BF16, decomposed via a 4-arm leave-one-out ablation into +31.6% from MLA-attention kernels and +16.6% from MoE routing — the architecture-dependent inverse of the dense-model result.
